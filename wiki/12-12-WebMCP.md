# 12-12 WebMCP

WebMCP is a hosting extension that exposes FDW API endpoints as structured tools consumable by AI agents via the W3C [WebMCP](https://webmcp.dev/) browser standard. When enabled, the server serves a generated JavaScript file at `/.well-known/webmcp.js` that registers tools through `navigator.modelContext.registerTool()`.

AI agents (Claude, browser-based agents, etc.) discover this file at the well-known URL, read the tool definitions, and can then call the server's endpoints directly with structured inputs.

---

## Registration

In `Program.cs`, register before `Build()` and map after:

```csharp
// Before Build()
builder.Services.AddWebMcp(typeof(Program).Assembly);

var app = builder.Build();

// After Build(), alongside other Map* calls
app.UseWebMcpApiKey();   // before UseAuthentication if using agent keys
app.UseAuthentication();
app.UseAuthorization();
app.MapWebMcp();
```

Pass any assemblies that contain your decorated endpoint classes. Multiple assemblies are supported:

```csharp
builder.Services.AddWebMcp(
    typeof(Program).Assembly,
    typeof(SharedEndpoints).Assembly);
```

**Package:** `Fdw.Hosting`

---

## Decorating Endpoints

Add `[WebMcpTool]` to any FastEndpoints endpoint class:

```csharp
[WebMcpTool("list_connections", "List all configured database connections")]
public sealed class ListConnectionsEndpoint : EndpointWithoutRequest<List<ConnectionDto>>
{
    // ...
}

[WebMcpTool("create_connection", "Create a new database connection")]
public sealed class CreateConnectionEndpoint : Endpoint<CreateConnectionRequest, ConnectionDto>
{
    // ...
}

[WebMcpTool("get_connection", "Get connection details by name", ReadOnly = true)]
public sealed class GetConnectionEndpoint : Endpoint<GetConnectionRequest, ConnectionDto>
{
    // ...
}
```

### Attribute Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `name` | `string` | Yes | Tool name exposed to agents. Snake_case recommended (e.g. `list_connections`). |
| `description` | `string` | Yes | Human-readable description shown to AI agents. Be specific. |
| `ReadOnly` | `bool` | No | Marks the tool as having no side effects. Adds `readOnlyHint: true` annotation. Default: `false`. |
| `HttpMethod` | `string` | No | Override the HTTP method (e.g. `"GET"`). Defaults to auto-detected method. |

---

## Route Resolution

The registry resolves routes in priority order:

1. **`public const string Route`** field on the endpoint class
2. **`public static string Route`** property on the endpoint class
3. **FastEndpoints `[Http*]` attribute** on the class (e.g. `[HttpGet("/api/connections")]`)

If no route can be resolved, the tool is skipped with a Warning log (`FDW-7196`).

---

## HTTP Method Resolution

Methods are determined in priority order:

1. `HttpMethod` property on `[WebMcpTool]` (explicit override)
2. FastEndpoints `[Http*]` attribute (`[HttpGet]` → `GET`, etc.)
3. Class name prefix heuristic: `Create*` → `POST`, `Update*` → `PUT`, `Delete*` → `DELETE`
4. Default: `GET`

---

## Input Schema Generation

The generator reflects over the endpoint's `TRequest` type (from `Endpoint<TRequest>` or `Endpoint<TRequest, TResponse>`) to produce a JSON Schema `inputSchema`. Supported CLR → JSON Schema mappings:

| CLR Type | JSON Type | Format |
|----------|-----------|--------|
| `string` | `string` | — |
| `bool` | `boolean` | — |
| `int`, `long`, `short` | `integer` | — |
| `double`, `float`, `decimal` | `number` | — |
| `Guid` | `string` | `uuid` |
| `DateTime`, `DateTimeOffset` | `string` | `date-time` |
| `DateOnly` | `string` | `date` |
| `TimeOnly` | `string` | `time` |
| `Nullable<T>` | (unwrapped) | — |

Complex types, collections, and arrays are skipped (omitted from the schema). `GET` and `DELETE` endpoints with no request type produce an empty schema.

All properties are listed as optional (`required: []`). There is no annotation-based required marker yet — agents infer required fields from the description.

## Generated JavaScript

The generated IIFE at `/.well-known/webmcp.js` looks like this:

```js
// Generated by FractalDataWorks WebMCP
// Registers AI agent tools via navigator.modelContext (WebMCP W3C standard)
(function() {
  if (!navigator?.modelContext) return;

  navigator.modelContext.registerTool({
    name: "list_connections",
    description: "List all configured database connections",
    annotations: { readOnlyHint: true },
    inputSchema: {
      type: "object",
      properties: {},
      required: []
    },
    execute: async function(input) {
      const r = await fetch("/api/connections", {
        method: "GET",
        headers: { "Accept": "application/json" }
      });
      if (!r.ok) return { error: r.status + " " + r.statusText };
      return await r.json();
    }
  });

  navigator.modelContext.registerTool({
    name: "create_connection",
    description: "Create a new database connection",
    inputSchema: {
      type: "object",
      properties: {
        "Name": { "type": "string" },
        "Server": { "type": "string" },
        "Database": { "type": "string" }
      },
      required: []
    },
    execute: async function(input) {
      const r = await fetch("/api/connections", {
        method: "POST",
        headers: { "Accept": "application/json", "Content-Type": "application/json" },
        body: JSON.stringify(input)
      });
      if (!r.ok) return { error: r.status + " " + r.statusText };
      return await r.json();
    }
  });

})();
```

The script is served with `Cache-Control: public, max-age=3600`. It is excluded from API description/Scalar docs.

## Startup Behavior

Discovery runs once during `MapWebMcp()` — after `Build()`, before `Run()`. It scans each provided assembly for concrete, non-abstract types with `[WebMcpTool]`. The registry is a singleton; generated JS is built on each request (cheap string concatenation).

Startup logs (at Debug/Info level):

| EventId | Level | Message |
|---------|-------|---------|
| 7194 | Debug | `Discovering WebMCP tools in assembly type '{typeName}'` |
| 7195 | Debug | `WebMCP tool registered: '{name}' → {method} {route}` |
| 7196 | Warning | `WebMCP tool skipped (no route resolved): '{typeName}'` |
| 7197 | Information | `WebMCP registration complete: {count} tool(s) registered` |
| 7198 | Trace | `Serving /.well-known/webmcp.js ({toolCount} tools)` |

## Agent API Key Authentication

WebMCP supports an "on behalf of" key model: each API key is associated with a real user so RBAC applies normally, plus an `agent` claim marks the request as bot-originated for audit logs.

### Configuration

```csharp
builder.Services.AddWebMcp(
    new[] { typeof(Program).Assembly },
    options =>
    {
        // Injected into every fetch() call in webmcp.js
        // This value is publicly visible — use a low-privilege key
        options.ClientApiKey = configuration["WebMcp:ClientApiKey"];

        // Keys the server will accept (loaded from secrets)
        options.AgentKeys =
        [
            new WebMcpAgentKey
            {
                Key    = configuration["WebMcp:Keys:Mike"],
                UserId = "user-id-for-mike",         // matches usr.Users Id
                Label  = "mike - claude dev agent",  // shown in audit logs
            },
        ];
    });
```

```csharp
// In the middleware pipeline — before UseAuthentication
app.UseWebMcpApiKey();
app.UseAuthentication();
app.UseAuthorization();
```

### How It Works

1. The generated `webmcp.js` includes `"X-Webmcp-Key": "<ClientApiKey>"` in every `fetch()` header.
2. `UseWebMcpApiKey()` middleware intercepts requests carrying that header.
3. The key is looked up in `AgentKeys` (exact `Ordinal` match).
4. On match, a `ClaimsPrincipal` is synthesized with:
   - `ClaimTypes.NameIdentifier` = the key's `UserId`
   - `ClaimTypes.Name` = the key's `Label`
   - `"agent"` = `"true"`
   - `"agent_label"` = the key's `Label`
5. `context.User` is replaced — downstream auth sees a real user. RBAC policies evaluate against the user's permissions in the normal way.
6. On no match: `401 Unauthorized`, no further processing.
7. Requests without the header pass through unmodified — normal JWT/cookie auth applies.

### Reading Agent Claims

```csharp
var isAgent = User.FindFirstValue("agent") == "true";
var agentLabel = User.FindFirstValue("agent_label");   // "mike - claude dev agent"
var userId = User.FindFirstValue(ClaimTypes.NameIdentifier);
```

### Key Security

| Concern | Guidance |
|---------|----------|
| `ClientApiKey` is in the public JS | Use a low-privilege, read-only key. Never reuse an admin key. |
| Keys in config | Store in environment variables or secret manager, not `appsettings.json`. |
| Key rotation | Add the new key to `AgentKeys`, remove the old one, redeploy. No downtime. |
| Scope | Decorate only list/get endpoints with `[WebMcpTool]` for agent keys. Keep mutations off WebMCP or behind separate authorization. |

### Startup Logs

| EventId | Level | Message |
|---------|-------|---------|
| 7199 | Warning | `WebMCP agent key rejected for route '{route}'` |
| 7200 | Information | `WebMCP agent key accepted: '{label}' acting as user '{userId}'` |
| 7201 | Debug | `WebMCP agent request authenticated: '{label}' (userId={userId}) → {route}` |

## Design Decisions

**No hard FastEndpoints dependency.** Route and HTTP method resolution uses attribute name string comparison rather than type references. This keeps `Fdw.Hosting` free from a hard coupling to a specific FastEndpoints version.

**Attribute-opt-in only.** Not every endpoint should be an AI tool. `[WebMcpTool]` is an explicit declaration of intent — endpoints without it are invisible to agents.

**All properties optional.** The schema marks all fields as optional. Required semantics belong in endpoint validation (FluentValidation), not the MCP schema. Agents use the description to understand what's needed.

**On-behalf-of key model.** Agent keys map to real users rather than introducing a separate "service account" concept. RBAC, audit trails, and permission checks all work without modification — the agent just runs as the user who generated the key.

---

## Limitations

- Complex request properties (arrays, nested objects) are omitted from the input schema
- No `required` fields — all inputs are marked optional
- No path parameter templating (e.g. `/api/connections/{name}`) — the route is used as-is
- Authentication is not handled within the generated JS
